## Slide 2 - What Is Informed Search?

Informed (heuristic) search uses problem-specific knowledge to guide the exploration of the state space toward promising regions. Unlike uninformed search, which treats all non-goal states symmetrically, informed search orders node expansion using an estimate of each state's promise.

The key construct is the **heuristic function** h(n):

h(n) = estimated cost of the cheapest path from node n to a goal state

If n is a goal state, h(n) = 0. The heuristic provides a lower-bound estimate (ideally) of remaining cost, allowing the algorithm to prioritize nodes likely to lead quickly to a solution.

Informed search is applicable whenever domain knowledge can be encoded as a heuristic. The quality of the heuristic directly determines search efficiency.

---

## Slide 3 - Greedy Best-First Search

Greedy best-first search expands the node that appears closest to the goal, according to the heuristic alone:

f(n) = h(n)

The frontier is a priority queue ordered by h(n). The algorithm is "greedy" because it always chooses the locally most promising node without considering the cost already incurred.

Properties:

- **Complete:** No - can get stuck in loops or follow a promising-looking path that leads to a dead end
- **Optimal:** No - does not account for path cost already incurred
- **Time complexity:** O(b^m) in the worst case, but can be much better with a good heuristic
- **Space complexity:** O(b^m)

Greedy best-first search resembles depth-first search in its tendency to follow a single path deeply, but it chooses branches based on heuristic promise rather than depth.

Example: In route finding, h(n) might be straight-line distance to the destination. Greedy search heads directly toward the destination on the map, potentially ignoring roads, traffic, or terrain.

## Slide 4 - A* Search: Combining Path Cost and Heuristic

A* search evaluates nodes using:

f(n) = g(n) + h(n)

where:

- g(n) = cost of the path from the initial state to node n (known exactly)
- h(n) = estimated cost from n to the goal (heuristic estimate)
- f(n) = estimated total cost of the cheapest solution through n

A* expands the node with the lowest f(n) value. It balances:

- How expensive the path so far is (g(n))
- How promising the remaining path appears (h(n))

Properties (critical results):

- **Complete:** Yes (if branching factor finite and step costs bounded below)
- **Optimal:** Yes, if h(n) is **admissible** (never overestimates true cost)
- **Time complexity:** Depends on heuristic quality; exponential in worst case
- **Space complexity:** O(b^d) - stores all generated nodes

A* is widely regarded as the best general graph-search algorithm when an admissible heuristic is available.

## Slide 5 - Admissible Heuristics

A heuristic h(n) is **admissible** if it never overestimates the true cost to reach a goal from n:

h(n) ≤ h*(n) for all n

where h*(n) is the actual cost of the optimal path from n to a goal.

Admissibility guarantees A* optimality. Intuition: an admissible heuristic is "optimistic" - it assumes the best-case remaining cost, so A* never overlooks a cheaper solution by overestimating a node's promise.

Examples of admissible heuristics:

- Romania road map: straight-line (Euclidean) distance to Bucharest (admissible because roads cannot be shorter than straight-line distance)
- 8-puzzle: number of misplaced tiles (admissible because each misplaced tile requires at least one move)
- 8-puzzle: Manhattan distance (sum of horizontal+vertical distances of tiles from goal positions - admissible and dominates misplaced-tiles)

---

## Slide 6 - Consistent (Monotone) Heuristics

A heuristic is **consistent** (or monotone) if, for every node n and every successor n' of n generated by action a:

h(n) ≤ c(n, a, n') + h(n')

where c(n, a, n') is the step cost from n to n'.

Consistency is a stronger condition than admissibility: every consistent heuristic is admissible, but not vice versa.

Important consequences of consistency:

- A* using a consistent heuristic is optimal (like admissible heuristics)
- A* with a consistent heuristic never re-expands a node (each node is expanded at most once)
- The f-values along any path are nondecreasing, so A* expands nodes in order of increasing f - analogous to UCS expanding in order of increasing g

For tree search, admissibility suffices for optimality. For graph search with re-opening, consistency ensures each node is settled once.

---

## Slide 7 - Dominance of Heuristics

If h₂(n) ≥ h₁(n) for all n (and both are admissible), then h₂ **dominates** h₁. A dominant admissible heuristic is strictly better for A* because:

- It expands no more nodes than h₁ (typically fewer)
- It remains admissible and thus preserves optimality

Example on the 8-puzzle:

- h₁(n) = number of misplaced tiles
- h₂(n) = Manhattan distance

Manhattan distance dominates misplaced tiles because every misplaced tile contributes at least 1 to both measures, but tiles displaced by multiple positions contribute more to Manhattan distance. A* with Manhattan distance expands fewer nodes.

This leads to a general method for constructing admissible heuristics: **relaxed problems**.

---

## Slide 8 - Admissible Heuristics from Relaxed Problems

A relaxed problem removes constraints from the original problem, making it easier to solve. The optimal cost in the relaxed problem is an admissible heuristic for the original problem because removing constraints can only reduce (or keep equal) the true cost.

Examples:

- 8-puzzle relaxed to allow tiles to move anywhere in one step: h(n) = number of misplaced tiles
- 8-puzzle relaxed to allow tiles to move to any adjacent square (ignoring blocking): h(n) = Manhattan distance
- Romania map relaxed to allow direct travel between any pair of cities: h(n) = straight-line distance

Relaxed problems are often easy to solve exactly (e.g., by counting or by formula), and their solutions provide admissible heuristics automatically.

---

## Slide 9 - Admissible Heuristics from Subproblems

Another heuristic construction method: identify a subproblem of the original problem whose solution cost is a lower bound on the full problem's cost.

Example: 8-puzzle. Consider only tiles 1-3 and ignore tiles 4-8. The cost to get tiles 1-3 into their goal positions (ignoring interference from other tiles) is a lower bound on the full 8-puzzle solution cost. Precomputing these subproblem costs (via pattern databases) yields powerful heuristics.

Pattern databases store precomputed optimal solution costs for subproblems, enabling O(1) heuristic lookup during search. This technique has solved the 15-puzzle and 24-puzzle optimally.

---

## Slide 10 - A* Optimality: Tree Search vs. Graph Search

**Tree Search:** A* with an admissible heuristic is optimal. Because the search tree may contain multiple paths to the same state, A* may expand the same state multiple times via different paths, but the first time a goal is popped from the frontier, its cost is optimal.

**Graph Search:**

- With an admissible heuristic: A* is optimal, but may re-expand nodes when a cheaper path to an already-expanded state is found
- With a consistent heuristic: A* is optimal and expands each node at most once - no re-expansion needed

The distinction matters for implementation: consistent heuristics allow a simpler "closed list" where expanded nodes are never revisited.

## Slide 11 - Memory-Bounded A*: IDA* and SMA*

A* stores all generated nodes in memory, which can be prohibitive. Two memory-bounded variants address this:

**Iterative Deepening A* (IDA*):**

- Each iteration performs a DFS with an f-cost cutoff
- Nodes with f(n) > cutoff are pruned; the next iteration's cutoff is the minimum f-value that exceeded the previous cutoff
- Complete and optimal (with admissible heuristic)
- Space complexity: O(bd) - linear in depth, like DFS
- Time complexity: can revisit nodes, but overhead is modest when f-values are well-distributed

**Simplified Memory-Bounded A* (SMA*):**

- Expands the best leaf node subject to available memory
- When memory is full, drops the worst leaf node (highest f-value), remembering its f-value in its parent
- Can continue search despite memory limits by re-expanding dropped nodes if needed

IDA* and SMA* trade repeated computation for bounded memory, making A* applicable to larger problems.

## Slide 12 - Heuristic Accuracy and Search Efficiency

The effective branching factor b* measures heuristic quality. If A* expands N nodes to find a goal at depth d:

N = 1 + b* + (b*)² + ... + (b*)^d

A well-designed heuristic makes b* close to 1 (near-linear search). A poor heuristic makes b* approach b (the actual branching factor), approaching uninformed search performance.

Empirically, heuristic accuracy has enormous practical impact:

- 8-puzzle: misplaced tiles expands thousands of nodes; Manhattan distance expands hundreds
- Heuristic design is the central engineering challenge in informed search

Better heuristics reduce the effective search space exponentially.

## Slide 13 - Informed Search in Practice: Application Domains

**Route Planning and Navigation:**

- Heuristic: straight-line distance or estimated travel time to destination
- Used in GPS navigation, robotics path planning, game AI navigation

**Puzzle Solving:**

- Heuristics from relaxed problems and pattern databases
- Used in automated solvers for Rubik's Cube, sliding puzzles, Sokoban

**Planning and Scheduling:**

- Heuristics estimate remaining work or constraint violations
- Used in manufacturing, logistics, and project planning

**Game Playing:**

- Evaluation functions estimate position strength (Chapter 8 builds on this)
- Combined with minimax and Monte Carlo Tree Search (Text Note 12)

**Search Engines (Text Note 17):**

- Ranking algorithms order results by estimated relevance - an informed process over a massive index
- Query processing uses heuristics to prune irrelevant documents early

## Slide 14 - Limitations of Heuristic Search

Despite its power, informed search faces limitations:

1. **Heuristic design is difficult:** Requires domain expertise and insight; there is no systematic procedure for discovering good heuristics
2. **Admissibility may be too strong:** In practice, slightly inadmissible heuristics can find near-optimal solutions much faster
3. **Memory remains a constraint:** Even IDA*/SMA* can be slow when re-expansion is frequent
4. **Heuristics can mislead:** An inaccurate heuristic can direct search away from the goal, worse than uninformed search in pathological cases
5. **Does not handle uncertainty:** Assumes deterministic actions and known state - not applicable to stochastic or partially observable environments (Chapter 7)

---

## Slide 15 - From Heuristic Search to Learning

Heuristics are typically hand-designed by domain experts. Modern AI increasingly **learns** heuristics from data:

- Neural networks learn evaluation functions for games (AlphaGo's policy and value networks - Text Note 12)
- Reinforcement learning learns value functions V(s) that estimate expected future reward (Text Note 09)
- These learned heuristics replace or augment hand-crafted ones

This bridges informed search and machine learning: search examines consequences, learning estimates promise. The combination underlies modern game-playing systems and many planning applications.

## Slide 16 - Heuristic Search and Agent Architecture

Informed search fits naturally with goal-based and utility-based agents (Chapter 2): the agent has a goal or utility function, and the heuristic estimates how close a state is to satisfying it. A utility-based agent can even use its utility function as a heuristic, guiding search toward high-utility states.

However, informed search still assumes a deterministic, fully observable environment with known actions. In partially observable or stochastic settings, the agent cannot know the exact state or outcome, so plain A* over physical states is insufficient. The agent must combine informed search with belief-state maintenance (Chapter 7) or reinforcement learning (Text Note 09).

## Slide 17 - Case Study: A* in GPS Navigation

A GPS navigation system is a concrete application of A*. The state space is the road network (nodes = intersections, edges = road segments), g(n) is the distance or travel time from the start, and h(n) is the straight-line distance to the destination - an admissible heuristic because no road can be shorter than a straight line.

A* expands intersections in order of f(n) = g(n) + h(n), focusing exploration toward the destination rather than radiating equally in all directions like Dijkstra's algorithm (uniform-cost search). Real systems add traffic data to edge costs and use hierarchical road networks (motorways before local streets) to speed search further. This is informed search at production scale.

---

## Slide 18 - When Heuristic Search Is Not Enough

Even with a strong heuristic, A* can be impractical when the state space is enormous or the heuristic is weak. In such cases, AI systems combine search with other methods:

- **Beam search:** keeps only the k best frontier nodes, bounding memory at the risk of missing the goal
- **Stochastic search:** simulated annealing and genetic algorithms (Chapter 6) escape local optima without exhaustive exploration
- **Learning:** value functions and policies (Text Notes 06, 09) replace hand-designed heuristics with learned estimates
- **Abstraction:** solve a coarse version of the problem first, then refine (hierarchical search)

The guiding principle remains the same as throughout Chapters 3-5: use the least computation that yields a solution of sufficient quality, and match the method to the structure of the problem.

---

## Slide 19 - Summary: Key Takeaways

1. Informed search uses problem-specific knowledge (heuristics) to guide node expansion order
2. The heuristic h(n) estimates the cost from n to the goal; h(n)=0 at goal states
3. Greedy best-first search uses f(n)=h(n) - fast but neither complete nor optimal
4. A* uses f(n)=g(n)+h(n) - complete and optimal with an admissible heuristic
5. Admissible heuristics never overestimate true cost; consistent heuristics satisfy the triangle inequality and prevent node re-expansion
6. Dominant admissible heuristics expand fewer nodes while preserving optimality
7. Relaxed problems and subproblems provide systematic methods for constructing admissible heuristics
8. IDA* and SMA* bound A*'s memory at the cost of potential re-expansion
9. Heuristic quality dramatically affects effective branching factor and search efficiency
10. Learned heuristics (neural networks, RL value functions) increasingly replace hand-designed ones
