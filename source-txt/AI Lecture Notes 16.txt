1. INTRODUCTION
============================================================

A recommender system is an AI system that uses information about users, items, and previous interactions to predict what a person might enjoy.

In this lesson, we learn how to build a movie recommender system that suggests movies to two people with different preferences.

The goal is to find a movie that both people are likely to enjoy.

Examples of recommender systems include:
- Netflix recommending movies and television shows.
- YouTube recommending videos.
- Amazon recommending products.
- Music platforms recommending songs and artists.
- Online stores recommending products based on previous purchases.

The project uses Python, a movie-rating dataset, and a machine learning library to generate personalized movie recommendations.

The main steps are:

1. Obtain and explore movie-rating data.
2. Generate general movie recommendations.
3. Add personal movie ratings.
4. Use user-user collaborative filtering to generate personalized recommendations.
5. Combine two people's ratings to recommend movies they may both enjoy.

KEY IDEA:
A recommendation system does not need to know exactly what a person will like. It uses available data to estimate which items are most likely to match their preferences.

3. STEP 1: OBTAINING AND EXPLORING THE DATA
============================================================

The first step in building a recommender system is obtaining useful data.

The MovieLens dataset provides ratings that many users have given to different movies.

A simplified ratings table might look like this:

User ID | Movie ID | Rating
--------|----------|-------
1       | 1        | 4.0
1       | 3        | 4.0
2       | 1        | 5.0
2       | 2        | 3.0

Each row represents a rating given by a user to a movie.

For example:
- User 1 rated Movie 1 as 4.0.
- User 1 rated Movie 3 as 4.0.
- User 2 rated Movie 1 as 5.0.
- User 2 rated Movie 2 as 3.0.

Notice that User 1 has no entry for Movie 2.

This does not necessarily mean User 1 disliked Movie 2. It means that the dataset does not contain a recorded rating for that user-movie pair.

------------------------------------------------------------
3.1. UNDERSTANDING MISSING DATA
------------------------------------------------------------

Most people do not watch every available movie. Therefore, most user-movie combinations have no recorded rating.

This creates a sparse dataset.

A sparse dataset contains many possible entries that are missing or unobserved.

For example:

             Movie A    Movie B    Movie C
User 1          4.0        —          5.0
User 2           —         3.0        —
User 3          4.5        —          4.0

The dashes represent missing ratings.

A recommender system should not automatically interpret a missing rating as a zero or a negative opinion.

Why?
- The user may not have watched the movie.
- The user may have watched it but never rated it.
- The user may not know the movie exists.

MovieLens can represent ratings by storing only the interactions that actually occurred instead of storing a value for every possible user-movie pair.

This reduces unnecessary storage and preserves the distinction between an observed rating and an unknown preference.

------------------------------------------------------------
3.2. WHY MOVIE METADATA MATTERS
------------------------------------------------------------

Movie IDs are useful for computers, but they are not very informative to people.

For example, a recommendation of Movie ID 25 does not tell a person what to watch.

A separate movie table provides human-readable information.

Example:

Movie ID | Title                 | Genre
---------|-----------------------|-------------
1        | Example Movie A       | Action
2        | Example Movie B       | Romance
3        | Example Movie C       | Comedy

The ratings and movie-information tables can be joined using their shared movie ID.

This allows the system to display movie titles and genres alongside ratings.

A database join combines related records from separate tables using a common field.

KEY IDEA:
The ratings table tells us how users rated movies. The movie-information table tells us what those movies are.

============================================================
4. STEP 2: GENERATING GENERAL RECOMMENDATIONS
============================================================

Before personalizing recommendations, the project first creates a general list of highly rated movies.

A simple method is to calculate the average rating for every movie.

The average rating is calculated as:

Average Rating = Sum of All Ratings / Number of Ratings

Example:

Movie A receives these ratings:
5, 4, 5, 4

Average Rating = (5 + 4 + 5 + 4) / 4
               = 18 / 4
               = 4.5

A system can calculate the average rating for each movie and sort the movies from highest to lowest.

However, this method has an important limitation.

------------------------------------------------------------
4.1. THE PROBLEM WITH AVERAGE RATINGS
------------------------------------------------------------

Suppose two movies have the following results:

Movie A:
- Average rating: 5.0
- Number of ratings: 1

Movie B:
- Average rating: 4.7
- Number of ratings: 1,000

If we sort only by average rating, Movie A ranks higher.

But one person's opinion is not necessarily a reliable indicator of a movie's overall quality or popularity.

Movie B has a slightly lower average but has received ratings from many more people.

This introduces the idea of sample size.

Sample size is the number of observations used to calculate a statistic.

A movie with very few ratings has a less reliable estimate of its overall audience rating than a movie with many ratings, assuming the ratings are collected comparably.

------------------------------------------------------------
4.2. USING A MINIMUM RATING COUNT
------------------------------------------------------------

One way to improve general recommendations is to require each movie to have a minimum number of ratings.

For example, the project might only consider movies that have at least 20 ratings.

The process becomes:

1. Calculate each movie's average rating.
2. Count how many ratings each movie received.
3. Remove movies with fewer than the chosen minimum number of ratings.
4. Sort the remaining movies by average rating.

This makes the results less likely to be dominated by movies rated by only one or two people.

However, the threshold is a design choice rather than a universal rule.

A threshold of 20 ratings may be suitable for one dataset but not for another.

Also, requiring more ratings does not guarantee that a movie is good or that it will suit a particular user.

------------------------------------------------------------
4.3. GENERAL RECOMMENDATIONS BY GENRE
------------------------------------------------------------

The project can further narrow its list by looking at genres that match each person's interests.

For example:
- One person prefers action movies.
- Another person prefers romance movies.

The system can identify highly rated movies within each person's preferred genres.

This produces more relevant recommendations than using one general list for everyone.

However, two people with very different preferences may still have little overlap between their lists.

That is why the project needs a personalized recommendation technique.

5. STEP 3: PERSONALIZING THE DATASET
============================================================

A recommender system cannot personalize recommendations effectively without information about the target user.

If the system has no information about a person's preferences, it must rely on general recommendations or other available information.

This is related to the cold start problem.

The cold start problem occurs when a recommendation system has insufficient information about a new user or item to make reliable predictions.

In this project, the system needs to learn what both movie-night participants like.

John-Green-Bot| The Princess Bride | 3.5

These ratings can be added to the existing MovieLens data.

5.2. WHY PERSONAL RATINGS HELP
------------------------------------------------------------

Personal ratings provide direct evidence about an individual's preferences.

The system can use these ratings to:
- Identify similar users.
- Predict ratings for unseen movies.
- Rank movies according to predicted preference.
- Produce recommendations tailored to each participant.

A useful test is to check a movie both participants have rated.

For example, if both participants rated The Princess Bride, the programmer can verify that the data has been imported and stored correctly.

KEY IDEA:
Before training or running a recommendation model, verify that the input data is correct. Incorrect data can lead to misleading recommendations even when the algorithm is implemented properly.

6. STEP 4: USER-USER COLLABORATIVE FILTERING
============================================================

User-user collaborative filtering is a recommendation technique that predicts what a person might like by examining the preferences of other users with similar rating patterns.

The central assumption is:

People who have rated some of the same items similarly may have similar preferences for other items.

For example:
- User A and User B both enjoy several science-fiction movies.
- User B gives a high rating to a science-fiction movie that User A has never seen.
- The system may predict that User A will also enjoy that movie.

This method uses relationships between users rather than relying only on movie genres or overall popularity.

------------------------------------------------------------
6.1. REPRESENTING USERS AS VECTORS
------------------------------------------------------------

A vector is an ordered collection of numbers.

A user's ratings can be represented as a vector, with each position corresponding to a movie.

Suppose there are three movies:

Movie 1: Inception
Movie 2: The Notebook
Movie 3: Casablanca

A user might have the following rating vector:

User A = [5.0, 1.0, 4.0]

Another user might have:

User B = [4.5, 1.5, 4.0]

These users have similar ratings for the movies they have both rated.

A third user might have:

User C = [1.0, 5.0, 2.0]

User C appears to have very different preferences.

The recommender system can use mathematical measures of similarity to identify users whose rating patterns are alike.

In real datasets, many entries are missing. The system must account for these missing ratings when calculating similarity.

------------------------------------------------------------
6.2. HIGH-DIMENSIONAL DATA
------------------------------------------------------------

In a user-user collaborative filtering model, each movie can be treated as a dimension in the user-rating space.

If the dataset contains 10,000 movies, the complete rating representation may have 10,000 dimensions.

Each dimension corresponds to one movie's rating.

A point in this high-dimensional space represents a user's ratings across the movies.

Although we cannot easily visualize 10,000 dimensions, the underlying idea is similar to plotting users based on ratings for just two movies.

For example:
- The horizontal axis represents ratings for Inception.
- The vertical axis represents ratings for The Notebook.

Users who rate both movies similarly may appear close together on the graph.

With more movies, the system performs analogous calculations in a much higher-dimensional space.

Important:
The graph is a simplified illustration. Actual recommender systems use mathematical similarity calculations, statistical methods, and data structures rather than relying on a person visually drawing clusters.

------------------------------------------------------------
6.3. FINDING SIMILAR USERS
------------------------------------------------------------

The algorithm identifies a group of users whose ratings are similar to those of the target user.

This group is often called a neighborhood.

For example, when generating recommendations for John-Green-Bot, the system finds users whose known movie ratings resemble his ratings.

It can then examine the movies those users have rated that John-Green-Bot has not yet rated.

The neighbors provide evidence for predicting his preferences.

A neighborhood is not necessarily the same as a formal cluster produced by a clustering algorithm. In many user-user collaborative filtering implementations, the system calculates user similarity and selects a neighborhood of the most similar users.

The precise method depends on the algorithm.

============================================================
7. MINIMUM AND MAXIMUM NEIGHBORHOOD SIZES
============================================================

The project allows the programmer to set minimum and maximum neighborhood sizes.

These settings control how many similar users can contribute to a prediction.

A. MINIMUM NEIGHBORHOOD SIZE

The minimum neighborhood size specifies the minimum number of neighbors required or targeted for a recommendation calculation, depending on the library's implementation.

B. MAXIMUM NEIGHBORHOOD SIZE

The maximum neighborhood size limits how many neighbors can contribute to a prediction.

For example, a configuration might use:
- Minimum neighborhood size: 3
- Maximum neighborhood size: 15

The model then uses a neighborhood of similar users within the configured limits, subject to the library's rules and available data.

------------------------------------------------------------
7.1. SMALL NEIGHBORHOODS
------------------------------------------------------------

A small neighborhood considers fewer users who are typically selected because their preferences are similar to the target user's preferences.

Potential advantages:
- Recommendations may be more personalized.
- The model may better reflect unusual or specific tastes.
- Less influence may come from people with different preferences.

Potential disadvantages:
- There may be too little data to make reliable predictions.
- Recommendations can be based on only a few users' opinions.
- The system may recommend obscure movies with limited evidence.

Example:
A relatively unknown movie receives excellent ratings from a small number of similar users. It may rank highly even though the wider audience has little familiarity with it.

------------------------------------------------------------
7.2. LARGE NEIGHBORHOODS
------------------------------------------------------------

A large neighborhood considers more users.

Potential advantages:
- More rating information may be available.
- Predictions may be possible for more movies.
- Recommendations may reflect broader preferences.

Potential disadvantages:
- Less similar users may influence the results.
- Recommendations may become more general.
- The system may lose some personalization.

Example:
If the neighborhood includes many users with different tastes, a widely watched movie may receive a strong predicted rating even if it is not especially suited to the target user.

------------------------------------------------------------
7.3. THE TRADE-OFF
------------------------------------------------------------

The goal is not simply to maximize or minimize the neighborhood size.

Instead, developers must balance:
- Similarity between users
- Amount of available data
- Prediction reliability
- Recommendation diversity
- Personalization
- Computational cost

There is no universally best neighborhood size.

The best settings depend on the dataset, the algorithm, and what the system is designed to achieve.

============================================================
8. PREDICTING RATINGS FOR UNSEEN MOVIES
============================================================

After finding a neighborhood of similar users, the model examines the movies those users have rated that the target user has not rated.

Suppose John-Green-Bot has never rated Casablanca.

Several of his similar users have rated it:
- Neighbor A: 5.0
- Neighbor B: 4.5
- Neighbor C: 4.0
- Neighbor D: 4.5

The model uses these ratings and the similarity between each neighbor and John-Green-Bot to estimate his likely rating.

The model might predict a rating of 4.6.

This is an example of a predicted rating, not an actual rating provided by John-Green-Bot.

The algorithm repeats the process for other movies that he has not rated.

It can then sort the movies by predicted rating and return a top-10 recommendation list.

The same process is carried out separately for the other participant.

------------------------------------------------------------
8.1. PREDICTED RATINGS VERSUS ACTUAL RATINGS
------------------------------------------------------------

Actual rating:
A score the user has already given to a movie.

Predicted rating:
An estimate of how the user might rate a movie based on available information.

These values should not be confused.

A prediction of 4.6 does not guarantee that the user will give the movie a 4.6 rating after watching it.

The user may dislike the movie for reasons that are not represented in the training data.

============================================================
9. WHY THE TWO RECOMMENDATION LISTS MAY NOT OVERLAP
============================================================

After generating personalized recommendations, the system might produce two top-10 lists with no movies in common.

This can happen when the users have substantially different preferences.

For example:
- One user prefers action and adventure.
- The other prefers romance and drama.

Each recommendation list can be reasonable for its individual user, yet the lists may fail to identify a movie suitable for both people.

This reveals an important distinction:

Recommending a movie to one person is a different task from recommending a movie to a group.

For group recommendations, the system needs to combine or balance multiple people's preferences.

The project addresses this challenge by creating a combined rating dataset.

============================================================
10. STEP 5: COMBINING TWO PEOPLE'S RATINGS
============================================================

The project creates a combined profile called the Jabril-Green-Bot hybrid.

This is a dataset that combines the movie preferences of both participants. It is not a physical robot or a new type of AI architecture.

The goal is to find movies that may satisfy both people.

The approach uses the following rules:

RULE 1: BOTH PEOPLE HAVE RATED THE MOVIE

If both participants rated a movie, calculate the average of their ratings.

Formula:

Combined Rating = (Person A's Rating + Person B's Rating) / 2

Example:

Jabril's rating of The Princess Bride = 4.5

John-Green-Bot's rating of The Princess Bride = 3.5

Combined Rating = (4.5 + 3.5) / 2
                = 8.0 / 2
                = 4.0

The combined dataset records a rating of 4.0 for this movie.

RULE 2: ONLY ONE PERSON HAS RATED THE MOVIE

If only one participant has rated the movie, the project keeps that person's rating.

Example:

Jabril's rating of Movie A = 5.0

John-Green-Bot has not rated Movie A.

Combined Rating = 5.0

The system includes the available rating rather than treating the missing rating as zero.

------------------------------------------------------------
10.1. ADVANTAGES OF THE COMBINED PROFILE
------------------------------------------------------------

Combining ratings creates one profile that approximately represents the group's preferences.

Potential advantages:
- It is simple to implement.
- It allows the same recommendation model to be reused.
- It can identify movies that balance multiple people's interests.
- It can support group activities, such as movie nights.

The combined profile can be passed to the collaborative filtering model to generate a new ranked list of movies.

------------------------------------------------------------
10.2. LIMITATIONS OF THE COMBINED PROFILE
------------------------------------------------------------

A simple average does not perfectly represent a group's preferences.

Consider this example:

Person A rates a movie: 5.0
Person B rates a movie: 1.0

Combined Rating = (5.0 + 1.0) / 2
                = 3.0

The average is 3.0, but neither person actually gave the movie a rating of 3.0.

One person loves the movie, while the other strongly dislikes it.

Averages can hide disagreements between group members.

Other limitations include:
- Keeping one person's rating when the other person's rating is missing may overstate the group's interest.
- Each person's opinion receives equal weight, regardless of how important the movie is to them.
- Averages do not guarantee that everyone will enjoy the recommended movie.
- Different group members may have different expectations for a successful recommendation.

A more advanced group recommendation system could use minimum satisfaction, weighted preferences, disagreement penalties, or other methods that explicitly consider whether all participants are likely to enjoy the choice.

KEY IDEA:
A combined rating is a useful approximation, not a guarantee of group satisfaction.

============================================================
11. GENERATING GROUP RECOMMENDATIONS
============================================================

Once the combined rating dataset has been created, it can be supplied to the collaborative filtering model.

The workflow is:

1. Collect ratings from all participants.
2. Combine their ratings according to the selected rules.
3. Create a combined user profile.
4. Find users whose preferences resemble that combined profile.
5. Predict ratings for movies the group has not rated.
6. Sort the movies by predicted rating.
7. Display the highest-ranked recommendations.

The model might recommend an unfamiliar movie such as Submarine or another movie that appears suitable for both participants.

The recommendations can be inspected and discussed before making the final decision.

The model provides suggestions; the people still choose which movie to watch.

------------------------------------------------------------
11.1. WHY THE GROUP PROFILE MAY WORK
------------------------------------------------------------

The combined profile gives the model a representation of shared preferences and interests.

For example:
- Person A enjoys action.
- Person B enjoys romance.
- Both enjoy stories with strong characters.

The model may recommend a movie that contains elements of both genres or otherwise fits the group's combined rating pattern.

However, the model only knows what is represented in the available data. It cannot automatically understand every reason that a person likes or dislikes a movie.

13. SCALABILITY AND COMPUTATIONAL COST
============================================================

A recommender system becomes more demanding as the amount of data increases.

A dataset with more movies and ratings may offer:
- More possible recommendations
- Better coverage of different interests
- More evidence for identifying similar users

However, larger datasets can also require:
- More storage
- More computation
- Longer model training or processing times
- More memory
- More careful optimization

A system must balance the benefits of additional data against the cost of processing it.

This is especially important for platforms that recommend content to millions or billions of users.

Practical techniques for scaling recommendation systems may include:
- Efficient similarity calculations
- Sparse matrix representations
- Sampling and approximation
- Caching frequent results
- Parallel processing
- More advanced recommendation algorithms

The best approach depends on the size of the system, the available resources, and the desired recommendation quality.

14. USER-USER COLLABORATIVE FILTERING VERSUS OTHER METHODS
============================================================

User-user collaborative filtering is only one way to build a recommendation system.

A. USER-USER COLLABORATIVE FILTERING

Looks for users with similar preferences and uses their ratings to predict what the target user might like.

Example:
People who enjoy similar movies may also enjoy another movie that one of them rated highly.

B. ITEM-ITEM COLLABORATIVE FILTERING

Looks for items that receive similar ratings or interactions from users.

Example:
People who like Movie A also tend to like Movie B, so Movie B may be recommended to someone who likes Movie A.

C. CONTENT-BASED RECOMMENDATION

Uses item characteristics, such as genre, subject, keywords, or descriptions, to recommend similar items.

Example:
A user who enjoys science-fiction movies may receive recommendations for other science-fiction movies.

D. LATENT FACTOR METHODS

Latent factor methods learn hidden numerical representations of users and items from interaction data.

These representations can capture patterns that are not explicitly provided as genres or categories.

For example, the model might learn that a user tends to enjoy movies with certain combinations of themes, styles, and audience preferences.

The learned factors do not necessarily correspond to clear human-readable concepts.

E. HYBRID RECOMMENDATION SYSTEMS

Hybrid systems combine multiple recommendation approaches.

For example, a movie platform might combine:
- Collaborative filtering
- Genre and content information
- Movie popularity
- User history
- Other contextual signals

Hybrid systems can help address weaknesses that occur when only one method is used.

16. COMMON MISTAKES AND MISCONCEPTIONS
============================================================

MISTAKE 1: ASSUMING A MISSING RATING MEANS ZERO

A missing rating usually means the user's preference is unknown, not that the user dislikes the movie.

MISTAKE 2: TRUSTING THE HIGHEST AVERAGE WITHOUT CHECKING THE NUMBER OF RATINGS

A perfect rating based on one person's opinion may be less reliable than a slightly lower average based on hundreds of ratings.

MISTAKE 3: ASSUMING SIMILAR USERS ALWAYS LIKE THE SAME MOVIES

Similarity provides evidence for a prediction, but it does not guarantee that two users will agree about every movie.

MISTAKE 4: CONFUSING PREDICTIONS WITH FACTS

A predicted rating is an estimate. It is not an actual rating supplied by the user.

MISTAKE 5: ASSUMING A LARGER NEIGHBORHOOD IS ALWAYS BETTER

A larger neighborhood provides more data but may include users whose preferences are less similar to the target user's preferences.

MISTAKE 6: ASSUMING THE AVERAGE OF TWO RATINGS GUARANTEES GROUP SATISFACTION

An average can conceal major disagreement between participants.

MISTAKE 7: ASSUMING MORE DATA AUTOMATICALLY SOLVES EVERY PROBLEM

More data can improve coverage, but the system still needs suitable algorithms, accurate data, thoughtful evaluation, and appropriate objectives.

MISTAKE 8: ASSUMING THE TOP RECOMMENDATION IS DEFINITELY THE BEST MOVIE

The top-ranked item is the model's highest-ranked candidate according to its prediction method. It may still be a poor choice for a particular person or group.

EXERCISE 1: CALCULATING AN AVERAGE RATING

A movie receives the following ratings:

4, 5, 3, 4, 5

Calculate the average rating.

Solution:

Average = (4 + 5 + 3 + 4 + 5) / 5
        = 21 / 5
        = 4.2

The average rating is 4.2.

EXERCISE 2: COMPARING MOVIES

Movie A has an average rating of 5.0 from 2 users.

Movie B has an average rating of 4.6 from 500 users.

Questions:
1. Which movie has the higher average?
2. Which movie has more supporting ratings?
3. Why might a recommendation system require a minimum number of ratings?

Expected explanation:
Movie A has the higher average, but Movie B has many more ratings. A minimum rating threshold can reduce the influence of movies whose high averages are based on very few observations.

EXERCISE 3: COMBINING RATINGS

Person A rates Movie X as 4.5.

Person B rates Movie X as 3.5.

Calculate the combined rating.

Solution:

Combined Rating = (4.5 + 3.5) / 2
                = 4.0

EXERCISE 4: HANDLING A MISSING RATING

Person A rates Movie Y as 5.0.

Person B has not rated Movie Y.

According to the simple method used in this project, what value enters the combined dataset?

Solution:
The combined dataset keeps the available rating of 5.0. It does not replace the missing rating with zero.

Limitation:
The value represents the available evidence, not proof that both people will enjoy the movie.

EXERCISE 5: CHOOSING A NEIGHBORHOOD SIZE

A recommender system generates very personalized but obscure recommendations when its neighborhood is small.

When its neighborhood is large, the recommendations become more widely known but less personalized.

Question:
What trade-off is illustrated?

Expected explanation:
A small neighborhood can emphasize similar users but provide limited data. A large neighborhood can provide more data but may include users with less similar preferences.

20. FINAL SUMMARY
============================================================

The movie recommender project demonstrates how to build a practical recommendation system from existing data.

The system begins with a dataset of movie ratings, adds movie titles and genres, and explores general recommendations. It then incorporates personal ratings and applies user-user collaborative filtering to predict which unseen movies each person might enjoy.

When the two individual recommendation lists fail to produce a shared choice, the project combines the participants' ratings into a single group profile and runs the recommendation model again.

The result is a ranked list of possible movies for the group.

The most important lesson is that recommendation systems depend on both data and design choices. Missing ratings, neighborhood size, limited information, and different user preferences all affect the quality of the results.

A recommendation model does not know with certainty what people will enjoy. It uses available evidence to make predictions, and those predictions must be evaluated in context.

The same principles can be applied beyond movies to music, books, online shopping, videos, restaurants, and many other recommendation tasks.
